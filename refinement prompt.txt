PASHUSETU — FINAL UX POLISH UPDATE
==================================

IMPORTANT:
The existing PashuSetu application is already built and working.

DO NOT rebuild the application.
DO NOT change the existing architecture.
DO NOT remove or break any existing workflow, state, role navigation, auto-demo, reset, case journey, phone simulations, maps, or animations.

This is a FINAL UX POLISH update focused on TWO things:

1. A much more attractive animated MVP/simulation introduction screen.
2. A first-time interactive user guide for EVERY role/screen.

Everything else should remain exactly as it currently works.

============================================================
PART 1 — ATTRACTIVE SIMULATION INTRODUCTION
============================================================

CURRENT BEHAVIOR:

When the user opens/reloads the application, the simulation disclaimer appears.

UPDATE THIS EXPERIENCE COMPLETELY.

Instead of showing a normal static warning modal, create a premium animated INTRODUCTION SEQUENCE.

The experience should feel like the opening of a high-end technology demonstration.

Think:

"system boot → explanation → reveal → enter simulation"

Do NOT make it look like a generic website popup.

PART 2 — INTERACTIVE USER GUIDE
============================================================

SECOND MAJOR UPDATE:

Every role needs its own interactive guided walkthrough.

Roles:

1. FARMER
2. PARAVET
3. VETERINARIAN
4. LAB TECHNICIAN
5. GOVERNMENT

When the user switches to a role for the FIRST TIME during the current session:

automatically launch a guided tour for that role.

The guide should explain:

- what this screen represents
- what each important section does
- what buttons the user can click
- what action should happen next
- what the role is responsible for

This should feel like a built-in product walkthrough/manual.

------------------------------------------------------------
9. IMPORTANT TOUR BEHAVIOR
------------------------------------------------------------

The guide must NOT block the entire UI unnecessarily.

Use a spotlight/onboarding style.

Dim the rest of the interface slightly.

Highlight the current target element.

Show a compact tooltip/card near the highlighted element.

Example:

┌─────────────────────────────┐
│ FARMER SIMULATION            │
│                              │
│ This is your farm           │
│ environment. It shows       │
│ livestock and live-simulated│

│                              │
│              SKIP     NEXT →│
└─────────────────────────────┘

The highlighted element should remain fully visible.

Use:

spotlight
soft glow
animated border
small pointer/arrow

------------------------------------------------------------
10. EVERY GUIDE MUST HAVE NEXT + SKIP
------------------------------------------------------------

Every tour step MUST contain:

[ SKIP ]

[ NEXT → ]

Never remove these buttons.

The user can:

NEXT
→ continue the guide.

SKIP
→ immediately close the guide and allow normal interaction.

IMPORTANT:

If the user skips the guide, DO NOT disable the application.

The application must work normally.

The guide is purely instructional.

------------------------------------------------------------
11. IMPORTANT INTERACTION RULE
------------------------------------------------------------

The guide should explain the NEXT ACTION.

For example:

Guide step:

"This is the simulation trigger.
Click this button to generate a livestock health event."

Then:

[ SKIP ] [ NEXT → ]

If the user clicks:

NEXT

the guide should move to the next important interaction.

If the user skips:

the guide disappears.

The user can then directly click the actual button.

If the user directly interacts with the actual application button WITHOUT following the guide:

the application should work normally.

DO NOT force the user to complete the tutorial.

The guide must never interfere with the actual functionality.

------------------------------------------------------------
12. IMPORTANT — USER ACTION SHOULD NOT BREAK THE GUIDE
------------------------------------------------------------

If the user clicks an actual highlighted button while the guide is open:

allow the real application action to execute.

Then intelligently move the guide to the next relevant step if appropriate.

Example:

Farmer guide says:

"Click SIMULATE HEALTH EVENT."

User clicks the real button.

The event starts.

The guide should detect that the action occurred and then show:

"Great. The simulated anomaly has now been detected."

NEXT →

Then continue to the phone alert.

This will make the guide feel interactive rather than like a slideshow.

18. FIRST-TIME ROLE LOGIC
============================================================

The guide should appear:

ONCE PER ROLE
PER CURRENT SESSION.

User opens Farmer:

Farmer guide appears.

User switches to Paravet:

Paravet guide appears.

User switches to Veterinarian:

Use a simple in-memory session state.
